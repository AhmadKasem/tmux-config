tmux-workspace technical reference

Component boundaries, installation ownership, observations, private state and explicit recovery.

Inspected 2026-09-08 · Revision: 53b778e + workspace migration

System context

tmux-workspace combines responsive terminal configuration and a local project dashboard. It runs entirely on one Linux host using tmux, Python, SQLite, curses and pinned shell plugins. Agents supply observational hook events; the workspace never calls a model or reads private transcript files. The terminal client and agent process are outside the workspace ownership boundary.

The root installer coordinates two components. Config owns copied themes, keys and mobile formatting. Overview owns its source-backed launcher, agent hook handlers, observations and recovery wrappers. Their shared boundary is tmux configuration and status options. Private runtime state remains outside the checkout.

Installation ownership

install.py validates dependencies, theme selection, hook structures, launcher ownership, existing recovery configuration and conflicting bindings before configuration writes. Existing inline or legacy sourced overview blocks are relocated into the root managed block. Unrelated top-level lines remain. Existing installed palettes are user-owned and are never overwritten by reinstallation.

Order is theme/copy configuration, overview and resurrect setup, continuum initialization, then mobile status. overview-integrate waits for a tmux target, serializes status initialization with a file lock, normalizes the continuum shell path and reapplies mobile status. This asynchronous completion avoids attempting restore before the first target exists. Reloads and theme changes initialize the theme before rebuilding integration.

Full install requires Python 3.13; config-only does not import overview or install agent hooks. A custom destination home receives its own default state directory. Normal installs preserve XDG and OVERVIEW_STATE_DIR selection. overview install delegates to the root entry point; config/install.py delegates with config-only.

Changed target files are backed up outside Git. Atomic replacements protect individual files; there is no all-files rollback transaction for an I/O failure. Installation is explicit and does not reload the live server. Restore backups or rerun after fixing an I/O failure.

Themes, clients and status

Nine theme files supply colors and tmux options. Storm is the fresh default. tmux-theme atomically changes the current.conf symlink and reloads the full configuration. Local palette edits survive installation; an explicit theme selection chooses another installed file.

Mobile status chooses compact output below 80 client columns. At 65 and 160 columns two attached clients can see independent status layouts. Pane labels instead use shared pane width: narrow panes omit directory detail. The desktop format uses tmux time expansion so its clock renders as a clock, not literal percent placeholders. Cosmic Pastel intentionally uses its original borders.

tmux-mobile-status saves the wide format in @tmux-mobile-wide-status and leaves one continuum interpolation outside the compact conditional. The full setup adds G; lowercase g is optional and preserves an unrelated binding. Copy mode uses vi keys and OSC 52 with explicit y/Enter copying. True-color override assumes a capable xterm-256color terminal.

Hook interfaces and runtime identity

Codex and Claude command hooks pass one JSON object on stdin. The CLI bounds hook input to 1 MiB and requires an object. Supported events map to start, prompt, tool, waiting, response, interrupt and end. Explicit child/subagent events are ignored. Tool requests for supported user-question tools become waiting observations. No hook approves an operation or sends instructions to an agent.

Handlers produce no stdout and observational failures exit zero with a bounded stderr report. Hooks require agent activation and trust; on-disk definitions alone do not prove activation. Legacy handler definitions remain unchanged when their complete metadata, arguments and resolved executable match the owned handler. Changed definitions require fresh trust review.

tmux identity includes socket, start time, kernel boot ID and server process birth identity. Pane IDs alone never survive a server restart. Process association comes from the live pane and ancestor process identity, not directory matching. Working becomes Unknown after two minutes without observations; waiting persists until further observed activity. Acknowledging response completion does not answer a permission wait.

Private data and concurrency

State defaults to XDG_STATE_HOME/tmux-overview or ~/.local/state/tmux-overview; OVERVIEW_STATE_DIR overrides it. Schema remains version 1. Projects retain names, notes, registration, ignore flags and review times. Conversations retain stable agent:session IDs, directories, labels, explicit label edits, status, bounded response excerpts, ready/acknowledgment timestamps and live associations. Events deduplicate input; meta stores installation and recovery bookkeeping; recoveries maps conversation and runtime to verified placeholders.

SQLite uses foreign keys, BEGIN IMMEDIATE transactions and a two-second busy timeout. Duplicate event IDs, older observations and stale-turn completions are rejected. Source events without unique IDs/timestamps cannot distinguish arbitrary replay from a new event. Excerpts are bounded to 400 printable characters, labels to 120 and project notes to 1000. Git worktrees group by common repository; each conversation keeps its exact directory.

Private state directories are 0700 and the database is 0600. Snapshot directories contain paths and command metadata and must also remain private. A consistent backup uses SQLite backup(), not a raw copy of a database that may be active. Migration preserves data and changes no schema. Backups and state are excluded from public content.

Evidence

overview/overview/state.py: Store, SCHEMA, state_dir, event, repository. tests/test_state.py covers concurrency, event ordering, labels, acknowledgment and grouping.

Paired saves and explicit recovery

Save acquires a bounded recovery lock, captures pre-save pane/conversation facts and invokes resurrect. The synchronous post-save hook verifies pre/post pane location and process identity, repairs empty-title fields and writes an adjacent manifest with stable conversation IDs and a SHA-256 binding to that exact snapshot. A success record is written only after verifying the new pair. Ambiguous locations generate warnings; directories alone never infer identity.

Restore validates the selected snapshot/manifest before layout changes. Resurrect runs with program replay and pane capture disabled and never-overwrite enabled. Newly created panes start a tokenized placeholder; only new, verified panes receive recovery mappings. The prior default-command is restored in finally handling. The two-second lock acquisition bound reports contention; vendor save/restore calls have a 60-second timeout.

Explicit resume checks directory and executable availability. If the recorded live instance still exists, it returns that pane. Otherwise it reuses only a matching, live, untouched placeholder or creates a new window. Pressing Enter relinquishes a placeholder to a shell under the same lock. Canonical executable comparison recognizes verified old symlink commands after relocation. Repeated restore protects occupied panes; repeated resume avoids launching the same observed instance twice.

Codex receives codex resume ID; Claude receives claude --resume ID, with the recorded working directory and no new prompt. Agent errors remain visible in their pane. The agent itself checks retained history. Continuum saves every five minutes only while status rendering and its multiple-server safeguard permit it; manual save remains available. Orphan manifests can remain after upstream snapshot retention and are harmless.

Dashboard and commands

The curses UI reuses a dedicated overview window and excludes its own panes from observations. It refreshes on input or a two-second timeout. The model groups projects, conversations and unmanaged panes; narrow terminals use selected-row details and wide terminals a side panel. Search covers names, notes, labels and bounded response excerpts.

Enter navigates without acknowledgment. Space expands projects; a acknowledges a response; e edits labels/notes; v marks a project reviewed; r explicitly resumes; s saves. The W/R/D cue counts waits, unacknowledged completions and registered projects due for review after three days. Ignored projects are excluded. CLI project commands, label, ack, list, status, save, restore, resume and doctor expose the same state. This is observational navigation, not a task lifecycle engine.

Evidence

overview/overview/cli.py, ui.py: model, status_line, run. presentation.py: render, fit, cells. Tests exercise 65/160-column curses output and navigation across moved/linked/closed panes.

Relocation, removal and rollback

Keep the original checkout usable while assembling the combined tree. Before local migration, save and verify a pair, back up configuration/hooks, copy snapshots with manifests and make a SQLite backup outside Git. Archive old directories outside the repository, then create compatibility symlinks to the new component directories. Cached hooks and placeholder commands continue executing through those paths. Keep the aliases until no agent or recovery record needs them.

Install and explicitly reload without restarting tmux or agents. Verify the selected theme, bindings, one cue, one save command and a newly paired snapshot. Rollback restores archived source directories and backed-up configuration, then reloads. Preserve newer private observations; restoring an older database is a separate recovery decision.

Overview uninstall removes its marked block, exact verified handlers, launcher and owned live G/g/cue/save settings. It preserves unrelated handlers, mobile/config files, private state and backups. Manually changed handler metadata is not considered owned. Config-only installation never uninstalls overview. Removing the checkout prematurely breaks source-backed commands.
